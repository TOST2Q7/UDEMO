# 05. HQ-SRV — `hq-srv.sh` и `dnsmasq.conf`

**Роль узла.** Главный сервер головного офиса:

* **DNS-сервер всего стенда** (dnsmasq) — зона `au-team.irpo`;
* **файловое хранилище**: программный RAID 0 из трёх дисков, раздаваемый по
  **NFS** клиентам;
* SSH-доступ для `sshuser`;
* позже — **веб-сайт** на Apache + PHP + MariaDB (`web.sh`, см.
  [09-web-services.md](09-web-services.md));
* позже — **удостоверяющий центр (УЦ)** для ГОСТ-сертификатов
  ([10-gost.md](10-gost.md)).

**Сеть.** Подключён к trunk-порту HQ-RTR, поэтому сам тегирует кадры:
интерфейс `enp7s1.100` (VLAN 100) с адресом `192.168.100.2/27` —
создаётся руками по подсказке из `hq-rtr.sh` до запуска скрипта.

---

## 1. Имя хоста, wget

```bash
hostnamectl set-hostname hq-srv.au-team.irpo
apt-get update && apt-get install wget
```

`wget` нужен, чтобы скачать `dnsmasq.conf` из репозитория. Без `-y`: если
пакет уже есть (обычно так), вопроса не будет.

## 2. DNS-сервер

```bash
wget -O "$DIR/dnsmasq.conf" "$(dirname "$RAW_URL")/dnsmasq.conf"
apt-get install -y dnsmasq
systemctl enable --now dnsmasq
rm -rf /etc/dnsmasq.conf
cp "$DIR/dnsmasq.conf" /etc/
systemctl restart dnsmasq
```

**Почему конфиг лежит отдельным файлом в репозитории**, а не heredoc-ом в
скрипте, как на HQ-RTR: он большой (записи для всех узлов, CNAME, PTR) и
его удобнее править и смотреть на GitHub как самостоятельный файл. За
основу взят **стандартный** `dnsmasq.conf` с комментариями (~700 строк), а
собственные настройки вписаны в его начало (строки 3–28) — так под рукой
остаётся штатная справка по всем опциям.

Порядок «установить → включить → заменить конфиг → перезапустить»:
пакет при установке кладёт свой конфиг, поэтому замена делается после
установки, а `restart` применяет новый файл.

### 2.1. Разбор `dnsmasq.conf`

**Общее поведение:**

| Строка | Смысл | Почему |
|---|---|---|
| `domain-needed` | не пересылать наружу запросы коротких имён без точки | `hq-srv` без домена не должен уходить в интернет-DNS |
| `bogus-priv` | не пересылать наружу обратные запросы для частных сетей | PTR для `192.168.x.x` в интернете бессмысленны и «светят» внутреннюю адресацию |
| `no-resolv` | не брать upstream из `/etc/resolv.conf` | сам HQ-SRV смотрит в `127.0.0.1` — иначе dnsmasq пересылал бы запросы сам себе |
| `domain=au-team.irpo` | локальный домен | для `expand-hosts` и DHCP (если бы был) |
| `server=77.88.8.8` | upstream для всех внешних имён | публичный Яндекс.DNS; так весь стенд получает интернет-имена через один сервер |
| `server=/au-team.irpo/192.168.0.2` | всё про `au-team.irpo`, чего нет локально, — спрашивать у BR-SRV | там Samba AD DC; только он знает служебные записи домена (`_ldap._tcp`, `_kerberos._tcp`, …), нужные для ввода машин в домен |
| `listen-address=127.0.0.1,192.168.100.2` | слушать loopback (для себя) и LAN-адрес (для остальных) | не отвечать на других адресах |
| `interface=*` | все интерфейсы | в сочетании с `listen-address` фактически ограничение задаёт именно он |
| `expand-hosts` | к коротким именам из `/etc/hosts` добавлять домен | имя из `/etc/hosts` станет доступно и как FQDN (строка дублируется ниже по файлу — на поведение не влияет) |
| `localise-queries` | при нескольких адресах имени отдавать тот, что в подсети спрашивающего | полезно для многоинтерфейсных узлов |
| `conf-dir=/etc/dnsmasq.conf.d` | подгружать дополнительные файлы | штатная строка ALT |

**Записи зоны:**

```
host-record=hq-rtr.au-team.irpo,192.168.100.1
cname=moodle.au-team.irpo,hq-rtr.au-team.irpo
cname=wiki.au-team.irpo,hq-rtr.au-team.irpo

address=/br-rtr.au-team.irpo/192.168.0.1
ptr-record=1.0.168.192.in-addr.arpa,br-rtr.au-team.irpo
address=/hq-srv.au-team.irpo/192.168.100.2
ptr-record=2.100.168.192.in-addr.arpa,hq-srv.au-team.irpo
address=/br-srv.au-team.irpo/192.168.0.2
ptr-record=2.0.168.192.in-addr.arpa,br-srv.au-team.irpo
address=/hq-cli.au-team.irpo/192.168.200.2
ptr-record=2.200.168.192.in-addr.arpa,hq-cli.au-team.irpo
```

Три разных механизма — и каждый выбран не случайно:

* **`host-record`** создаёт **сразу A и PTR**. Использован для `hq-rtr`,
  потому что на него ссылаются CNAME-ы: `cname=` в dnsmasq работает только
  с целью, известной из `host-record`/`/etc/hosts`/DHCP, но **не** из
  `address=`.
* **`cname=moodle…, wiki…`** — псевдонимы веб-сервисов. Требование
  задания: сервисы `moodle` и `wiki` доступны по своим именам, которые
  указывают на HQ-RTR (там предполагается проброс/прокси к реальным
  серверам). Псевдоним, а не отдельная A-запись — при смене адреса
  роутера менять придётся одну строку.
* **`address=/имя/IP`** — A-запись. `address` в dnsmasq отдаёт только прямую
  запись, поэтому к каждой добавлена **`ptr-record`** для обратной зоны.
  Формат PTR: октеты адреса в обратном порядке + `.in-addr.arpa`
  (`192.168.0.1` → `1.0.168.192.in-addr.arpa`). Обратные записи — требование
  задания и нужны, например, SSH и Kerberos, которые проверяют имя по адресу.

**Про `hq-cli` → `192.168.200.2`.** HQ-CLI получает адрес по DHCP из пула
`.2–.10`, поэтому запись верна, только если клиент получил первый адрес
пула (типичный случай для единственного клиента). Скрипты, которым нужен
точный адрес HQ-CLI (`br-srv.sh`, `gost.sh`), поэтому **не полагаются на
DNS**, а сканируют пул.

**Взаимодействие с Samba.** HQ-SRV — «главный» DNS, BR-SRV (DC) —
авторитет по AD-записям. HQ-SRV пересылает незнакомые имена домена на DC;
DC пересылает всё чужое обратно на HQ-SRV (`dns forwarder=192.168.100.2` в
`samba.sh`). Цикла не возникает: DC авторитетен для `au-team.irpo` и
отвечает сам (или NXDOMAIN), а HQ-SRV отвечает на свои `address=` локально,
не пересылая.

## 3. SSH и пользователь `sshuser`

```bash
useradd -u 2027 -m sshuser
echo "sshuser:P@ssw0rd" | chpasswd
gpasswd -a sshuser wheel
echo "sshuser ALL=(ALL) NOPASSWD: ALL" >> /etc/sudoers
sed -i 's/#Port 22/Port 2027/' /etc/openssh/sshd_config
sed -i 's/#PermitRootLogin without-password/PermitRootLogin no/' /etc/openssh/sshd_config
echo "AllowUsers sshuser" >> /etc/openssh/sshd_config
echo "MaxAuthTries 2" >> /etc/openssh/sshd_config
echo "Banner /etc/openssh/banner" >> /etc/openssh/sshd_config
echo "Authorized access only" > /etc/openssh/banner
systemctl restart sshd
```

Базовые элементы (пользователь, wheel, sudo, порт, root) — как у
`net_admin` на маршрутизаторах ([03-hq-rtr.md §1.9](03-hq-rtr.md#19-пользователь-net_admin)).
Серверная специфика:

| Настройка | Зачем |
|---|---|
| `-u 2027` | фиксированный UID — **требование задания**. Практически одинаковый UID на всех серверах важен для NFS: права на файлы в NFS передаются числами, и одинаковый UID означает «тот же пользователь» на разных машинах |
| `AllowUsers sshuser` | белый список: войти по SSH может **только** этот пользователь, даже если на сервере есть другие с паролями |
| `MaxAuthTries 2` | после двух неверных попыток соединение рвётся — замедляет подбор пароля |
| `Banner` | текст до ввода пароля; юридическое предупреждение «доступ только для авторизованных» |

Директивы добавляются через `>>` в **конец** файла. В sshd действует
правило «первое вхождение побеждает», поэтому это работает, только пока в
стандартном конфиге эти параметры закомментированы (так и есть в ALT).

## 4. RAID 0

```bash
mdadm --create --verbose /dev/md0 -l 0 -n 3 /dev/sd[b-d]
mdadm --detail -scan > /etc/mdadm.conf
echo -e "n\n\n\n\n\nw" | fdisk /dev/md0
mkfs.ext4 /dev/md0p1
mkdir /raid
echo "/dev/md0p1 /raid ext4 defaults 0 0" >> /etc/fstab
mount -a
```

**Зачем.** Требование задания: объединить три дополнительных диска
(`sdb`, `sdc`, `sdd`) в один массив и смонтировать в `/raid`.

**Почему RAID 0.** Уровень задан заданием. RAID 0 (чередование) даёт
суммарный объём всех дисков и максимальную скорость, но **ноль
отказоустойчивости**: выход из строя любого диска уничтожает весь массив.
Для учебного стенда это приемлемо; для реальных данных выбрали бы RAID 5/6
или 10.

Построчно:

| Команда | Смысл |
|---|---|
| `mdadm --create /dev/md0 -l 0 -n 3 /dev/sd[b-d]` | собрать программный массив уровня 0 из 3 устройств; `sd[b-d]` — glob-шаблон bash на `sdb sdc sdd` |
| `mdadm --detail --scan > /etc/mdadm.conf` | записать описание массива (UUID) в конфиг, чтобы при загрузке он собирался под **тем же** именем `md0` — иначе он мог бы стать `md127`, и запись в fstab перестала бы работать |
| `echo -e "n\n\n\n\n\nw" \| fdisk /dev/md0` | неинтерактивно создать раздел: `n` — новый, 4 пустых Enter — все значения по умолчанию (primary, №1, от начала до конца), `w` — записать |
| `mkfs.ext4 /dev/md0p1` | файловая система ext4 — стандарт для Linux |
| `/etc/fstab` + `mount -a` | постоянное монтирование; `mount -a` монтирует всё из fstab сразу, заодно проверяя, что строка корректна (ошибка в fstab иначе всплыла бы только при перезагрузке) |

`0 0` в fstab — не делать dump-бэкап и не проверять fsck при загрузке
(можно было бы `0 2`; для стенда не критично).

## 5. NFS

```bash
apt-get install -y nfs-server
systemctl enable --now nfs
mkdir /raid/nfs
chown -R 99:99 /raid/nfs
chmod 777 /raid/nfs
echo "/raid/nfs 192.168.200.0/28(rw,sync,no_subtree_check)" >> /etc/exports
systemctl restart nfs
touch /raid/nfs/test
```

**Зачем.** Требование задания: общий каталог на RAID, доступный клиентам
офиса по сети. HQ-CLI монтирует его в `/mnt/nfs`.

| Элемент | Смысл |
|---|---|
| `/raid/nfs` | подкаталог, а не весь `/raid`: наружу отдаётся только то, что предназначено для общего доступа |
| `chown 99:99` | владелец — непривилегированный «никто» (`nobody`); в него NFS отображает root клиента (`root_squash` по умолчанию) |
| `chmod 777` | запись для всех — так любой пользователь клиента сможет создавать файлы независимо от своего UID. Грубо, но надёжно для стенда |
| `192.168.200.0/28` | доступ **только из клиентской VLAN 200**. Серверы и филиал не видят шару — принцип минимальных прав |
| `rw` | чтение и запись |
| `sync` | сервер подтверждает запись только после сброса на диск — медленнее, но при сбое не теряются «подтверждённые» данные |
| `no_subtree_check` | отключает проверку, что файл внутри экспортируемого подкаталога; рекомендуемый по умолчанию вариант, избегает проблем при переименовании открытых файлов |
| `restart nfs` | перечитывает `/etc/exports` |
| `touch test` | тестовый файл — на клиенте `ls /mnt/nfs` должен его показать, это наглядное доказательство, что монтирование работает |

## 7. DNS самого сервера

```bash
chattr -i /etc/resolv.conf 2>/dev/null
cat > /etc/net/ifaces/enp7s1/resolv.conf <<EOF
nameserver 127.0.0.1
search au-team.irpo
EOF
[ -d /etc/net/ifaces/enp7s1.100 ] && cp … /etc/net/ifaces/enp7s1.100/resolv.conf
cp /etc/net/ifaces/enp7s1/resolv.conf /etc/resolv.conf
```

* `127.0.0.1` — сервер спрашивает **свой** dnsmasq.
* `chattr -i` — снятие атрибута «неизменяемый». Ранние версии скрипта
  защищали `/etc/resolv.conf` от перезаписи этим атрибутом; без снятия
  запись сейчас упала бы. На чистой системе команда просто ничего не
  делает (ошибки подавлены `2>/dev/null`).
* Копия в `enp7s1.100/resolv.conf` — по подсказке `hq-rtr.sh` там записан
  временный `77.88.8.8`. Поскольку адрес сервера висит именно на
  `enp7s1.100`, etcnet при рестарте сети применил бы **этот** файл и вернул
  бы публичный DNS. Условие `[ -d … ]` — на случай, если VLAN-интерфейс
  назван иначе.

## 8. Проверки

Интересные сверх стандартных:

| Проверка | Смысл |
|---|---|
| `RAID array /dev/md0 exists` → `grep "^md0 :" /proc/mdstat` | ядро видит собранный массив |
| `/raid is mounted` → `mountpoint -q` | именно точка монтирования, а не просто каталог |
| `Local DNS answers hq-srv.au-team.irpo` → `getent hosts … \| grep "^192.168.100.2 "` | сквозная проверка: resolv.conf → dnsmasq → правильный ответ. `getent` идёт через NSS, как обычные программы |
| `Local DNS answers moodle/wiki (CNAME)` | CNAME-ы реально разрешаются |
