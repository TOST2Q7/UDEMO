# 02. ISP — `isp.sh`

**Роль узла.** «Провайдер»: единственная машина стенда с выходом во внешнюю
сеть. Раздаёт интернет двум офисам через NAT и связывает их между собой
(маршрутизирует трафик GRE-туннеля). Также это **сервер точного времени** для
всего стенда, а позже на нём работает nginx — обратный прокси для
веб-сервисов ([09-web-services.md](09-web-services.md)), переводимый затем
на HTTPS с ГОСТ-сертификатами ([10-gost.md](10-gost.md)).

**Интерфейсы.**

| Интерфейс | Куда смотрит | Адрес | Как получает |
|---|---|---|---|
| `enp7s1` | во внешнюю сеть | динамический | DHCP (не трогается скриптом) |
| `enp7s2` | к HQ-RTR | `172.16.1.1/28` | статически |
| `enp7s3` | к BR-RTR | `172.16.2.1/28` | статически |

---

## 1. Имя хоста

```bash
hostnamectl set-hostname isp.au-team.irpo
```

Задаётся **полное доменное имя (FQDN)**, а не просто `isp`. Требование
задания; кроме того, FQDN используется в проверках и приглашении командной
строки. `hostnamectl` пишет его в `/etc/hostname` — значение сохраняется
после перезагрузки.

## 2. Часовой пояс

```bash
apt-get update
apt-get install -y tzdata
if [ -z "$(find /usr/share/zoneinfo -name Krasnoyarsk)" ]; then
    echo "... tzdata did not install" >&2
elif ! timedatectl set-timezone Asia/Krasnoyarsk; then
    rm -f /etc/localtime
    ln -s /usr/share/zoneinfo/Asia/Krasnoyarsk /etc/localtime
fi
```

**Зачем.** Часовой пояс — требование задания (Красноярск, UTC+7). Он важен
не только «для красоты»: одинаковое и правильное время на узлах нужно для
Kerberos (Samba AD отвергает билеты при расхождении часов больше чем на
5 минут), для проверки срока действия сертификатов и для корректных логов.

**Почему так сложно, а не одной командой.** Образ **ALT JeOS** (минимальный)
может поставляться **без базы часовых поясов** — пакета `tzdata`. Тогда
`timedatectl set-timezone` падает с ошибкой «неизвестный пояс». Поэтому:

1. `apt-get update` + `install tzdata` — гарантируем наличие базы.
2. `find … -name Krasnoyarsk` — проверяем, что файл пояса реально появился.
   Если нет — дальше делать нечего, выводим диагностику в stderr.
3. Штатный путь — `timedatectl set-timezone`.
4. Если `timedatectl` всё равно отказался (бывает, когда `systemd-timedated`
   не видит пояс), — делаем то же самое вручную: `/etc/localtime` это просто
   символическая ссылка на файл пояса, её и создаём.

Последние три команды (`timedatectl | grep`, `ls -l /etc/localtime`, `date`)
— наглядный вывод результата прямо во время выполнения.

## 3. Сервер времени (chrony)

```bash
apt-get install -y chrony
cat > /etc/chrony.conf <<EOF
local stratum 5
allow 172.16.0.0/16
allow 192.168.0.0/16
allow 10.10.10.0/30
EOF
systemctl enable --now chronyd
systemctl restart chronyd
for i in $(seq 10); do
    chronyc tracking | grep -qE '^Stratum +: 5$' && break
    sleep 1
done
```

**Зачем.** Все остальные узлы синхронизируют время с ISP
([00-overview.md §4.6](00-overview.md#46-синхронизация-времени-chrony)).
Требование задания — ISP служит источником времени со стратумом 5.

| Строка | Смысл | Почему так |
|---|---|---|
| `local stratum 5` | раздавать **собственные часы** как эталон, даже без синхронизации с внешним источником | стенд может не иметь доступа к публичным NTP; без этой строки chrony, не синхронизированный сам, отказывал бы клиентам |
| `5` | «расстояние» до эталонных часов | достаточно высокий стратум: если у клиента окажется реальный источник (стратум 1–4), он будет предпочтён этому «локальному» |
| `allow 172.16.0.0/16` | принимать запросы от WAN-адресов маршрутизаторов | офисы ходят к ISP **через NAT**, так что все LAN-узлы видны ISP как `172.16.1.2`/`172.16.2.2` |
| `allow 192.168.0.0/16` | принимать запросы от LAN-адресов напрямую | на случай, если трафик придёт без NAT |
| `allow 10.10.10.0/30` | сеть туннеля | аналогично, с запасом |

По умолчанию chrony **не обслуживает** никого, кроме localhost, —
`allow` обязателен, иначе клиенты не получили бы ответа.

Цикл после рестарта ждёт до 10 секунд, пока `chronyc tracking` не покажет
`Stratum : 5`: локальный эталон включается не мгновенно, и проверка в
конце скрипта без этой паузы дала бы ложный FAIL.

Сервер времени настраивается **до** сети: ему не нужна сеть, а часовой
пояс уже выставлен.

## 4. Интерфейсы `enp7s2`, `enp7s3`

```bash
mkdir -p /etc/net/ifaces/{enp7s2,enp7s3}
cat <<EOF > /etc/net/ifaces/enp7s2/options
BOOTPROTO=static
TYPE=eth
...
EOF
echo '172.16.1.1/28' > /etc/net/ifaces/enp7s2/ipv4address
echo '172.16.2.1/28' > /etc/net/ifaces/enp7s3/ipv4address
```

В свежей системе etcnet знает только интерфейс, через который шла
установка (`enp7s1`). Для остальных каталоги нужно создать —
`{enp7s2,enp7s3}` раскрывается bash-ем в два пути.

Разбор ключей файла `options`:

| Ключ | Значение | Зачем |
|---|---|---|
| `BOOTPROTO=static` | адрес берётся из `ipv4address` | это шлюз для офиса — адрес должен быть постоянным и известным |
| `TYPE=eth` | обычный Ethernet | etcnet по типу выбирает, как поднимать интерфейс |
| `CONFIG_WIRELESS=no` | не Wi-Fi | не запускать wireless-обработчики |
| `SYSTEMD_BOOTPROTO=dhcp4` | метод для systemd-networkd | **не используется**, т. к. ниже `SYSTEMD_CONTROLLED=no`; значение из шаблона ALT |
| `CONFIG_IPV4=yes` | включить IPv4 | стенд целиком на IPv4 |
| `DISABLED=no` | интерфейс включён | иначе etcnet его пропустит |
| `NM_CONTROLLED=no` | NetworkManager не трогает | чтобы две подсистемы не конфликтовали |
| `SYSTEMD_CONTROLLED=no` | systemd-networkd не трогает | то же |

Итог: интерфейсом управляет **только etcnet**, и это однозначно.

**Почему именно эти адреса.** `.1` в каждой `/28` — первая используемая
позиция, традиционно отдаваемая шлюзу. Маршрутизаторы офисов получат `.2`.

## 5. Маршрутизация (IP forwarding)

```bash
sed -i "s/net.ipv4.ip_forward = 0/net.ipv4.ip_forward = 1/" "/etc/net/sysctl.conf"
```

По умолчанию Linux **не пересылает** пакеты между интерфейсами — он хост, а
не маршрутизатор. Без этого параметра пакеты от HQ-RTR в интернет (и от
HQ-RTR к BR-RTR) просто отбрасывались бы.

Правится файл `/etc/net/sysctl.conf` — его применяет etcnet при рестарте
сети, так что настройка постоянная. `sed` заменяет готовую строку из
стандартного файла ALT, поэтому шаблон точно совпадает с её форматом
(с пробелами вокруг `=`).

## 6. NAT

```bash
apt-get install iptables -y
iptables -t nat -A POSTROUTING -o enp7s1 -j MASQUERADE
iptables-save > /etc/sysconfig/iptables
systemctl enable --now iptables
```

**Зачем.** Адреса `172.16.x.x` — частные, во внешней сети они не
маршрутизируются. `MASQUERADE` подменяет адрес отправителя на адрес
`enp7s1` у всех пакетов, **уходящих наружу**, и запоминает соединение, чтобы
вернуть ответы.

Разбор правила:
* `-t nat` — таблица трансляции адресов;
* `-A POSTROUTING` — цепочка «после принятия решения о маршруте», т. е.
  когда уже известен выходной интерфейс;
* `-o enp7s1` — **только** для трафика, уходящего во внешнюю сеть. Трафик
  между `enp7s2` и `enp7s3` (офис ↔ офис, в том числе GRE) идёт **без NAT** —
  это принципиально: GRE-туннель настроен на реальные адреса `172.16.1.2` и
  `172.16.2.2`, и подмена сломала бы его;
* `MASQUERADE` (а не `SNAT --to …`) — потому что адрес `enp7s1` получается по
  DHCP и может измениться; MASQUERADE каждый раз берёт текущий.

**Сохранение.** Правила iptables живут в памяти ядра и пропадают при
перезагрузке. `iptables-save > /etc/sysconfig/iptables` сбрасывает их в
файл, а сервис `iptables` (`enable --now`) при загрузке восстанавливает их из
этого файла.

## 7. Рестарт сети

```bash
systemctl restart network
```

Применяет всё записанное в `/etc/net/...`: поднимает `enp7s2`/`enp7s3` с
адресами и включает forwarding из `sysctl.conf`. Выполняется **после** NAT,
чтобы к моменту появления трафика от офисов правило уже было.

## 8. SSH: разрешён вход root

```bash
sed -i 's/#*PermitRootLogin.*/PermitRootLogin yes/' /etc/openssh/sshd_config
systemctl enable --now sshd
systemctl restart sshd.service
```

**Почему на ISP root по SSH разрешён**, хотя на всех остальных узлах
запрещён: на заключительном этапе `gost.sh` на HQ-SRV копирует ключи и
сертификаты на ISP командой `scp … root@172.16.1.1:~/` — других
пользователей на ISP не создаётся. ISP по легенде — оборудование
провайдера, а не компании, и политика «никакого root по SSH» к нему не
относится.

**Почему шаблон `#*PermitRootLogin.*`** — он совпадает со строкой
независимо от того, закомментирована она или нет и какое значение там
стояло. Так замена срабатывает при любом исходном состоянии конфига (в
отличие от шаблонов на других узлах — см. [11-notes.md](11-notes.md)).

`enable --now` — на JeOS sshd может быть не включён; `restart` — чтобы
перечитать изменённый конфиг, если он уже работал.

## 10. Проверки

| Проверка | Что именно проверяет | Почему так |
|---|---|---|
| Hostname | `hostnamectl --static` | статическое имя, а не временное |
| tzdata installed | `rpm -q tzdata` | ALT — RPM-система |
| `/etc/localtime -> Asia/Krasnoyarsk` | куда указывает ссылка | покрывает оба пути настройки (timedatectl и ручной) |
| Local time is UTC+7 | `date +%z` = `+0700` | итоговый эффект — время действительно сдвинуто |
| chronyd active / enabled | сервис работает и в автозапуске | |
| `local stratum 5` в конфиге, `Stratum : 5` в `chronyc tracking` | конфиг **и** реальное состояние | сервер действительно раздаёт время с нужным стратумом |
| Interface up / Address | `ip addr show`, `grep` адреса | адрес реально на интерфейсе, а не только в файле |
| IP forwarding | строка в `/etc/net/sysctl.conf` | постоянная настройка |
| NAT MASQUERADE | `iptables -t nat -C …` | `-C` (check) — ищет **точное** правило в ядре, без вывода таблиц |
| iptables at boot | `systemctl is-enabled` | правило переживёт перезагрузку |
| SSH root login | `^PermitRootLogin yes` | `^` — строка не закомментирована |
| SSH active | `systemctl is-active` | демон работает |

## 11. NEXT STEP

Баннер предлагает руками прописать маршрутизаторам WAN-адреса:

```
HQ router:  172.16.1.2/28, default via 172.16.1.1, nameserver 77.88.8.8
BR router:  172.16.2.2/28, default via 172.16.2.1, nameserver 77.88.8.8
```

Это минимум, нужный маршрутизатору, чтобы **скачать свой скрипт**: адрес в
сети ISP, маршрут по умолчанию через ISP и публичный DNS (внутреннего ещё
нет). Всё остальное сделают `hq-rtr.sh` / `br-rtr.sh`.
